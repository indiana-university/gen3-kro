# config/ — Environment-Specific Input Files

All manually-edited configuration files live here. This directory is
**gitignored** (real files only) — example templates are tracked.

## Setup

Copy each `.example` file, remove the `.example` suffix, and fill in your values:

```bash
cp config/shared.auto.tfvars.json.example  config/shared.auto.tfvars.json
cp config/ssm-repo-secrets/input.json.example  config/ssm-repo-secrets/input.json
# Place your GitHub App private key (.pem) in config/ssm-repo-secrets/
```

## Files

| File | Purpose | Consumed By |
|------|---------|-------------|
| `shared.auto.tfvars.json` | **Single source of truth** — Terraform inputs, Terragrunt stack values, and backend bucket/region config | Terragrunt stacks, `container-init.sh` |
| `ssm-repo-secrets/input.json` | GitHub App credentials for ArgoCD repo access | `scripts/ssm-repo-secrets/generate-ssm-payload.sh` |
| `ssm-repo-secrets/*.pem` | GitHub App private key(s) | Referenced by `input.json` |

## Argo CD Repo Credentials

Public GitOps repositories do not need repository credential secrets. Leave
`ssm_repo_secret_names` as `{ "repos": [] }` in `shared.auto.tfvars.json`;
Terraform will not read AWS Secrets Manager or create Argo CD repository
secrets.

For private GitOps repositories, add one entry per Argo CD repository credential
secret. The preferred form matches the `scripts/ssm-repo-secrets` input/output
schema; Terraform reads `name` and `ssm_secret_name` from each entry:

```json
"ssm_repo_secret_names": {
  "repos": [
    {
      "name": "addons",
      "ssm_secret_name": "/example/csoc/addons/git-credentials"
    },
    {
      "name": "fleet",
      "ssm_secret_name": "/example/csoc/fleet/git-credentials"
    }
  ]
}
```

The legacy map form is still supported: `{ "addons": "/example/secret" }`.
Blank names or blank secret IDs are ignored. The secret value must use the
Argo CD repository secret payload generated by `scripts/ssm-repo-secrets`.

### Unused Files (not required)

| File | Notes |
|------|-------|
| `terraform.tfvars` | Terraform variables are in `shared.auto.tfvars.json` |
| `backend.hcl` | Backend bucket/region config is in `shared.auto.tfvars.json`; Terragrunt units own their state keys |
| `secrets.yaml` | Terragrunt reads `spokes`, `developer_identity` from `shared.auto.tfvars.json` |

The fleet stack creates one per-spoke state at a time. Set `TG_SPOKE_ALIAS` when
more than one enabled spoke is present. Keep
`developer_identity.allow_devcontainer_assume_role` false unless direct manual
access to spoke accounts is explicitly required.

Generated script logs and reports use `outputs/YYYY-MM-DD/`. Terragrunt writes
separate `<action>-core.log` and `<action>-<unit>.log` files plus native JSON
run reports under `outputs/YYYY-MM-DD/terragrunt/<stack>/`. Files that serve as
inputs to another command, including `outputs/argocd-password.txt` and
`outputs/ssm-repo-secrets/output.json`, keep a stable undated path.

## Security

- **Never commit** real config files — they contain account IDs, credentials, and secret paths.
- The `.gitignore` ignores everything in `config/` except `*.example` and `README.md`.
- Keep private keys (`.pem`) in `config/ssm-repo-secrets/` only.
